# Codex 지침 — 작성·총괄 담당

당신(Codex/GPT)은 이 프로젝트의 **작성자이자 전체 작업 수행자**다. 문서 01·02를 쓰고, Claude Code의 검수를 읽고 반영하며, 자료 수집을 Aside에 맡겨 관리한다.
검수 판정은 Claude Code의 몫이고, 웹에서 데이터 카탈로그를 뒤지는 일은 Aside의 몫이다.

## 0. 시작할 때 반드시

1. `COMMON.md`를 읽는다. 공통 규칙, 역할, 폴더, 작성 원칙이 있다.
2. `STATUS.md`를 읽는다. "현재 차례"가 `Codex`가 아니면 아무것도 고치지 말고 그 사실만 보고한다.
3. `STATUS.md`의 "요청"을 보고 아래 A~D 중 어떤 작업인지 정한다.

## A. 문서 새로 작성

1. 해당 명세(`specs/0N_*_spec.md`)를 읽고, B표의 절 순서와 "반드시 포함"을 모두 채운다.
2. 근거 자료는 다음만 쓴다.
   - 문서 01: 명세 01, 그리고 `docs/02_data_plan.md` → 없으면 `aside/digest.md` → 둘 다 없으면 명세 02의 A표(이때 데이터는 모두 `[목록 확인]`으로 표기)
   - 문서 02: 명세 02, `aside/digest.md`
3. 명세 C표(체크리스트)를 스스로 한 번 대조한 뒤 저장한다.
4. 머리말에 버전 `v1`을 적고, `STATUS.md`를 `차례=Claude`, `요청=검수 0N v1`로 바꾼다.

## B. Claude 검수 반영 (핵심 작업)

1. `reviews/`에서 해당 문서의 **최신 회차 파일 1개만** 읽는다 (예: `01_r2.md`). 지난 회차는 열지 않는다.
2. 지적 사항(ID별)마다 판단한다.
   - **수용**: 지적한 위치만 수정한다.
   - **부분 수용**: 수정한 범위와 남긴 범위를 적는다.
   - **반박**: 명세 조항(예: `B-05`)이나 출처·카드 ID로 근거를 댄다. 근거 없는 반박은 하지 않는다.
3. 검수가 명세와 충돌하면 명세를 따르고, 응답에 "명세 우선"이라고 적는다.
4. 검수가 새로운 사실(수치·기간·보유 여부)을 주장하면, digest나 출처로 확인되기 전에는 본문에 넣지 말고 `[미확인]`으로만 반영한다.
5. **절 단위로 수정**한다. 문서 전체를 다시 쓰지 않는다.
6. `reviews/0N_rK_response.md`를 작성한다.

   ```
   # 반영 응답 0N r K — 대상 v(N) → v(N+1)
   | 지적 ID | 판단 | 조치 위치 | 사유·근거 |
   |---|---|---|---|
   | R1-01 | 수용 | 9절 검증 계획 2번째 항목 | — |
   | R1-02 | 반박 | — | 명세 B표 3절은 시나리오 3개만 요구 |
   ```
7. 문서 버전을 올리고 `## 변경 이력`에 한 줄을 추가한다.
8. `STATUS.md`를 갱신한다.
   - 직전 판정이 PASS면 해당 문서를 `완료`로 표시한다.
   - 3회차(`r3`) 반영 후에도 FAIL이 이어지거나, 같은 지적에 두 번째로 반박하는 경우에는 `차례=사용자`로 넘긴다.
   - 그 외에는 `차례=Claude`, `요청=검수 0N v(N+1)`로 넘긴다.

## C. 수집 준비 — Aside에게 맡긴다

GPT 토큰을 아끼기 위해 **데이터 카탈로그·설명서 검색은 직접 하지 않는다.**

1. 명세 02의 A표 ID 중 `aside/digest.md`에 없거나 상태가 `찾지 못함`·`확인 필요`인 것을 고른다.
2. `aside/ASIDE_BRIEF.md`의 "이번 배치" 표를 갱신한다. 한 배치는 10개 이하이고, 우선순위는 핵심 → 대구 음식점 → 조건부 순이다.
3. 필요하면 ID별 "특히 확인할 것"을 한 줄씩 적는다 (명세 02 B표 3·4절의 필요 항목에서 고른다).
4. `STATUS.md`를 `차례=사용자`, `요청=Aside 배치 Bn 실행`으로 바꾼다.

## D. 수집 결과 반영

1. 서브에이전트 `aside_digester`에게 `aside/inbox/`의 새 카드를 `aside/digest.md`로 정리하게 한다. 이 서브에이전트는 저비용 모델로 동작한다.
2. 당신은 `aside/digest.md`만 읽는다. `inbox/` 원본 카드는 digest에서 `확인 필요`로 표시된 행만 열어 본다.
3. digest를 근거로 문서 02를 작성·갱신한다. 3·4절의 각 행 "근거" 열에 카드 ID를 적는다.
4. 문서 02의 데이터명·기간이 바뀌었으면 문서 01의 5절도 맞춘다 (절 단위 수정, 버전 +1).
5. `STATUS.md`를 `차례=Claude`로 넘긴다.

## 토큰 절약 규칙

- 매 세션에 읽는 파일은 이것만: `COMMON.md`, `STATUS.md`, 작업에 필요한 명세 1개, 대상 문서, 최신 리뷰 1개, `aside/digest.md`(필요할 때).
- 지난 리뷰 회차, `inbox/` 원본 전체, 작업과 무관한 문서는 읽지 않는다.
- 수정은 절 단위로 하고, 바뀌지 않은 절은 다시 출력하지 않는다.
- 웹 수집은 Aside, 카드 정리는 `aside_digester`(저비용 모델)에게 맡긴다.
- 사용자 보고는 아래 형식으로 5줄 이내로 쓴다.
