## B. 필수 절과 담아야 할 내용

| 절 | 제목 | 반드시 포함 |
|---|---|---|
| 1 | 사업 개요 | 한 문장 정의(여러 공실의 업종과 입점 순서를 함께 설계하고, 입점 후 결과로 다시 조정). 출품 설명 인용문 1개. **집적과 잠식의 구분**: 같은 업종 집적은 수요를 만들 수 있으며, 줄일 대상은 같은 시간대·가격대·고객 목적을 겨냥해 기존 소비를 나눠 갖는 입점 |
| 2 | 고객과 사업 모델 | 초기 고객은 여러 공실을 조정할 수 있는 상가 운영사·건물주·상권 관리 조직이고, 개별 창업자 추천만으로는 안 되는 이유. 표(고객의 문제 / 서비스의 결정 / 제공 결과 / 입점 후 서비스 / 수익 모델 **제안**). 추천과 실제 계약·입점 결정은 별개 |
| 3 | 사용 사례 | **가상 사례임을 명시**. 조건이 다른 공실 3개. 업종보다 먼저 검토할 수요 가설 1개. 시나리오 표 3개(개별 매출 우선 / 상권 조합 우선 / 순차 입점) + 확인할 점. 유동인구가 많고 매출이 적다는 것만으로 수요가 있다고 판단하지 않음 |
| 4 | 서비스 흐름과 AI 활용 | 6단계 표(공실 등록 → 지역 수요 진단 → 입점 영향 추정 → 전체 조합 설계 → 소규모 검증 → 입점 후 재설계), 열은 단계 / 이용자와 서비스 / AI·분석 역할 / 결과물. AI 구현 방향: 수요 예측과 입점 영향 추정이 중심이고 언어모델은 입력·설명 보조. 유사 상권 탐색, 비교 지역 대조, 수리 최적화와 AI 예측의 역할 구분. 이동 기록 없이 소비 동선을 제시하지 않고, 관측 자료로 인과를 확정하지 않음 |
| 5 | 사용할 제공 데이터 | 표(데이터 / 사용 목적 / 반드시 확인할 항목). 데이터명·기간은 `docs/02` 또는 `aside/digest.md`와 일치. 데이터 사용 핵심 조건 5개 이상(프랜차이즈≠전체 점포, 공통 분석 기간, 다른 연도 자료 동시점 결합 금지, 기관 간 동일 점포 ID 가정 금지, 점포별 자료가 없으면 상권 단위로 범위 축소) |
| 6 | 추가 확보할 데이터 | 표(추가 데이터 / 확보 방식 **제안** / 필요한 이유). 공실 조건, 전체 점포·개폐업 이력, 임대료·시설비, 메뉴·가격·영업시간, 입점 전후 실적, 미충족 수요(설문·팝업) |
| 7 | 핵심 차별화 | 입점 예정까지 반영한 재계산 예시. 흐름 `현재 상권 분석 → 입점 예정 반영 → 첫 입점 결과 관측 → 다음 입점 재설계`. 결과는 단일 정답이 아닌 3안(우선 검토 / 수요 부진 시 부담 작은 안 / 소규모 검증 후 결정) |
| 8 | 배달 효율화 결합 | **확장 기능**으로 위치. 평가 질문 3개. 대구로 항목 제공 시에만 확장하며, 라이더 기록이 없으면 가정을 명시한 시뮬레이션으로 제한 |
| 9 | 공모전 시제품 범위 | 한 지역, 공실 3~5개, 후보 업종 5~8개. 화면 표 4개(상권 진단 지도 / 공실 조합 비교 / 입점 계획 갱신 / 검증 화면). 검증 계획(시간 분할 평가, 실행 조건 충족률, 개별 추천 대비 조합 추천 비교, 기존 점포 변화, 다양성만으로 성공 판단 금지, 시뮬레이션과 실제 효과 구분) |
| 10 | 우선 실행할 일 | 번호 목록 5~8개, 데이터 확인부터 현장 검증 순 |
| — | 자료 근거와 한계 | 근거 자료, 수행하지 않은 것(데이터 열람·시장성·효과 실증), 제안에 그치는 부분 |
